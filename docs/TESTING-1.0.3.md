# راهنمای آزمون روی گوشی واقعی + نصب و ارتقا — نسخهٔ 1.0.3 (versionCode 23)

**تاریخ:** ۲۰۲۶-۱۱-۱۵  |  **مبنای:** سند جامع چک‌لیست — بخش ۲۶ تا ۲۸

> این سند دو کارکرد دارد: (۱) چک‌لیست عملی آزمون برای کارفرما — علامت‌زدن این چک‌لیست همان «گزارش آزمون واقعی» تحویل‌دادنی شمارهٔ ۶ سند جامع است؛ (۲) راهنمای رسمی نصب/ارتقا (تحویل‌دادنی شمارهٔ ۱۰).

---

## بخش اول: ساخت و نصب

### ساخت APK (خودکار)

1. هر push به شاخهٔ main → GitHub Actions → workflow **build-apk.yml**
2. در تب Actions صفحهٔ مخزن، آخرین run موفق را باز کنید → artifact با نام `rahyab-apk-debug`
3. داخل آن: APKهای `universal`، `arm64-v8a`، `armeabi-v7a`، `x86_64` + فایل `SHA256SUMS.txt`
4. بررسی صحت: `sha256sum -c SHA256SUMS.txt` (در ترموکس)

### نصب از بالای نسخهٔ ۱٫۰٫۲ — حفظ اطلاعات کاربر

1. APK جدید را مستقیم باز کنید و نصب کنید (**بدون حذف نسخهٔ قبلی**)
2. اندروید «به‌روزرسانی» را نشان می‌دهد؛ تأیید کنید
3. پس از نصب: زبان، تنظیمات سخنگو، بسته‌های آفلاین، گزارش‌های ذخیره‌شده و مکان‌های ثبت‌شده همگی باید سر جای خود باشند
4. اگر پیام «برنامه نصب نشد» دیدید: امضای APK متفاوت است — در این صورت از Update داخل خود برنامه یا همان مخزن استفاده کنید و قبل از نصب از گزارش‌ها خروجی نگیرید (نسخه‌های CI همه با یک امضا ساخته می‌شوند)

**چرا امن است؟** مهاجرت‌های دیتابیس این نسخه فقط «افزودن» است: `reports.db` نسخهٔ ۳→۴ (۹ ستون nullable) و فایل جدید `traffic.db` — هیچ جدول/داده‌ای حذف یا بازسازی نمی‌شود. نسخهٔ قبلی برنامه هم با همین فایل‌ها کار می‌کند (بازگشت‌پذیر).

## بخش دوم: آزمون‌های پایه (۳۰ دقیقه — یک گوشی)

- [ ] نصب از بالای ۱٫۰٫۲ → باز شدن → زبان دری → تنظیمات قبلی پاک نشده
- [ ] نقشه، جست‌وجو، مسیریابی کوتاه، صدای راهنما — همه مثل قبل کار می‌کنند (قانون «حفظ قابلیت‌ها»)
- [ ] ثبت گزارش با **شدت جدید**: دکمهٔ گزارش → نوع «تصادف جاده‌ای» → انتخاب شدت «زیاد» → ذخیره → پیام موفق
- [ ] تنظیمات پیشرفتهٔ ترافیک (لمس طولانی دکمهٔ ترافیک): وضعیت موتور ترافیک نمایش داده می‌شود («بدون دادهٔ زندهٔ ترافیک» در شروع — **این صحیح است**) + کلید مشارکت + شمار نمونه‌ها
- [ ] GPS خاموش → مسیریابی → گفت‌وگوی روشن‌کردن → تنظیمات → روشن → بازگشت → ادامهٔ خودکار (آزمون بستهٔ اصلاح ۲، دوباره تأیید شود)
- [ ] هنگام ناوبری، خط کوچک وضعیت GPS زیر دستور دیده می‌شود: «GPS: قوی/متوسط/ضعیف/بدون اتصال»

## بخش سوم: آزمون گزارش زنده و تأیید اجتماعی (دو گوشی — بخش ۹)

- [ ] گوشی A: گزارش «انسداد کامل جاده» ثبت کند (با یادداشت)
- [ ] گوشی B (اینترنت روشن): روی نقشه همان نقطه را لمس کند → برگهٔ «تأیید می‌کنم / رد می‌کنم» باز شود → تأیید
- [ ] دو رأی تأیید از دو گوشی متفاوت → در `GET /api/v1/reports` فیلد `verification: confirmed` شود
- [ ] سه رأی رد → گزارش از فهرست فعال حذف شود
- [ ] گوشی C همان گزارش را در فاصلهٔ نزدیک دوباره ثبت کند → سرور پاسخ `merged:true` بدهد و ردیف تازه نسازد
- [ ] هر گوشی برای هر گزارش فقط یک رأی مؤثر باشد (رأی دوباره: `already_voted`)

## بخش چهارم: آزمون واقعی موتور ترافیک (بخش ۲۷ — بدون هیچ دادهٔ دستی)

**پیش‌زمینه:** برای این آزمون حداقل **۳ گوشی** با حساب‌های مجزا لازم است (قانون اعتماد: <۳ راننده = «ناکافی»). فیلم/اسکرین‌شات هر مرحله ثبت شود (تحویل‌دادنی شمارهٔ ۱۲).

**سناریوی پیشنهادی — خیابان کم‌سرعت یا نقطهٔ شلوغ (مثلاً نزدیک بازار):**

1. هر ۳ گوشی: اینترنت روشن، GPS روشن، ناوبری یا رانندگی آزاد فعال، کلید «اشتراک‌گذاری ناشناس سرعت» روشن
2. سه گوشی **هم‌زمان** داخل یک محدودهٔ ~۵۰۰ متری با سرعت واقعاً کم (زیر ۱۵ km/h) رانندگی کنند — **این ترافیک واقعی است، نه ساختگی**
3. بعد از ~۲–۳ دقیقه رانندگی کم‌سرعت، در گوشی چهارم (یا همان‌ها) `GET /api/v1/traffic/states?bbox=...` را در مرورگر باز کنید: باید وضعیت `severe` یا `extreme` با `drivers >= 3` برگردد
4. روی نقشهٔ گوشی‌ها همان محدوده نقطهٔ قرمز/نارنجی با برچسب «ترافیک سنگین/بسیار شدید • اعتماد …» دیده شود
5. **سناریوی کنترل (منفی):** سه گوشی با سرعت عادی (بالا از پایه) در جادهٔ آزاد → وضعیت باید «عادی» یا بدون داده بماند — نه ترافیک کاذب
6. **سناریوی ضدخطا:** در پارکینگ یا پشت چراغ سرخ ایست کامل → شمار نمونه‌های در انتظار رشد نکند (زیر ۳ km/h نمونه ساخته نمی‌شود)
7. **هشدار مسیرمحور:** گوشی A در مسیریابی به سمت محدودهٔ ترافیک برود → پیش از رسیدن (تا ۳ کیلومتر) هشدار صوتی «ترافیک سنگین در فاصلهٔ …» شنیده شود؛ گوشی‌ای که مسیرش از آن نقطه نمی‌گذرد یا خلاف جهت است → **هیچ** هشداری نشنود
8. **پایان دوره:** پس از رفع ترافیک واقعی و رانندگی سریع سه گوشی از همان قطعه، وضعیت از فهرست فعال حذف شود (پایان با بازیابی سرعت)

**ثبت نتیجه:** جدول زیر را پر کنید و به این سند اضافه کنید:

| آزمون | زمان | گوشی‌ها | نتیجهٔ مورد انتظار | نتیجهٔ واقعی | وضعیت |
|---|---|---|---|---|---|
| تشخیص ترافیک واقعی (۳ راننده) | | | severe/extreme | | |
| جادهٔ آزاد → کاذب نه | | | عادی/بدون داده | | |
| ایست در چراغ/پارکینگ → نمونه نه | | | شمار ثابت | | |
| هشدار هم‌جهت | | | صوت دری | | |
| بدون هشدار به خلاف جهت | | | سکوت | | |
| پایان دوره با بازیابی سرعت | | | حذف از فعال | | |

## بخش ششم: انتشار رسمی (بخش ۲۸) — پس از پاس همهٔ آزمون‌ها

1. Secret های امضا در مخزن تنظیم باشد (docs/SIGNING.md) تا build-apk.yml نسخهٔ امضاشده بسازد
2. تگ `v1.0.3` بزنید: `git tag v1.0.3 && git push origin v1.0.3`
3. Release رسمی با عنوان «راه‌یاب 1.0.3 — موتور ترافیک خودکار» + متن تغییرات + `versionCode: 23` (Update داخلی برنامه همین متن را می‌خواند)
4. آپلود هر چهار APK + SHA256SUMS.txt به Release (ترموکس: `gh release upload v1.0.3 ./*.apk SHA256SUMS.txt`)
5. استقرار Worker جدید: با push خودکار انجام می‌شود (deploy-worker.yml) — نیازمند دو Secret ثبت‌شده: `CLOUDFLARE_API_TOKEN` و `CLOUDFLARE_ACCOUNT_ID`
6. تا وقتی Worker جدید مستقر نشود، برنامه جدید هم سالم کار می‌کند (مسیرهای ترافیک ۴۰۴ می‌دهند و برنامه بی‌صدا «بدون دادهٔ زنده» نشان می‌دهد) — فقط هشدارها/تأیید اجتماعی پس از استقرار فعال می‌شوند

## بخش هفتم: بازگشت (Rollback)

- **برنامه:** نصب دوبارهٔ APK نسخهٔ ۱٫۰٫۲ روی ۱٫۰٫۳ مشکلی ندارد (ستون‌های جدید nullable اند)
- **Worker:** `git revert` آخرین کامیت و push → استقرار خودکار نسخهٔ قبلی؛ جدول‌های ترافیک جدید بدون مصرف‌کننده می‌مانند و پس از پاک‌سازی کرون خالی می‌شوند
- **دیتابیس:** پیش از استقرار `npx wrangler d1 export rahyab-reports --output=backup.sql`
