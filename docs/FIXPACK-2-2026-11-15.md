# بستهٔ اصلاح ۲ — تکمیل گزارش‌های جاده‌ای، همگام‌سازی و بومی‌سازی

**تاریخ:** ۲۰۲۶-۱۱-۱۵  |  **مبنای:** کامیت `3df60e8` (بعد از بستهٔ اصلاح ۱ که خودتان پوش کرده بودید)  |  **نسخهٔ جدید:** 1.0.3 (versionCode 23)

## یک جمله دربارهٔ جایگاه این بسته

بستهٔ اصلاح ۱ که خودتان پوش کرده بودید (کامیت e294716) بخش بزرگی از کار را درست انجام داده بود: اتصال گزارش‌ها به سرور، صف آفلاین، آدرس API، جریان GPS اولین اجرا و بومی‌سازی گسترده. این بسته **۹ شکاف باقی‌ماندهٔ** همان کار را نسبت به سند جامع تکمیل می‌کند — بدون هیچ بازنویسی و بدون حذف هیچ قابلیت یا داده‌ای.

## مهاجرت‌های دیتابیس — امن، مستند، قابل‌بازگشت

### سمت گوشی (SQLite — reports.db نسخهٔ ۲ → ۳)

- چه می‌کند: `ALTER TABLE pending_reports ADD COLUMN client_uuid TEXT` + پرکردن ردیف‌های قدیمی با UUID تصادفی پایدار.
- تضمین‌ها: هیچ جدولی حذف/بازسازی نمی‌شود؛ هیچ داده‌ای تغییر نمی‌کند؛ اگر ستون از قبل موجود باشد، خطا بی‌صدا گرفته می‌شود (اجرای دوباره امن است).
- بازگشت (Rollback): ستون nullable است؛ نسخهٔ قبلی برنامه آن را نادیده می‌گیرد. نصب دوبارهٔ APK نسخهٔ 1.0.2 بدون هیچ مشکلی کار می‌کند.
- پشتیبان‌گیری: لازم نیست (فقط افزودن)؛ برای اطمینان: در ترموکس `adb backup` یا کپی `reports.db` از `/data/data/af.rahyab.app/databases/` روی گوشی روت‌شده — یا هیچ، چون داده در جدول reports دست‌نخورده می‌ماند.

### سمت سرور (Cloudflare D1 — live_reports)

- چه می‌کند: Worker در نخستین POST پس از استقرار، خودش `ALTER TABLE live_reports ADD COLUMN client_uuid TEXT` و `CREATE UNIQUE INDEX IF NOT EXISTS idx_live_reports_client_uuid ...` را اجرا می‌کند؛ در خطای «ستون موجود است» ادامه می‌دهد. نیازی به اجرای دستی هیچ دستوری نیست.
- تضمین‌ها: فقط افزودن؛ داده‌های موجود دست‌نخورده؛ اجرای چندباره امن.
- بازگشت: استقرار دوبارهٔ نسخهٔ قبلی Worker از تاریخچهٔ گیت (`git revert`)؛ ستون اضافی بی‌ضرر می‌ماند.
- پشتیبان‌گیری اختیاری پیش از استقرار: `npx wrangler d1 export rahyab-reports --output=backup.sql`

## اقدام کارفرما پس از push این بسته

1. **بیلد APK:** خودکار با push به main — `.github/workflows/build-apk.yml` → artifact `rahyab-apk-debug` (فایل APK + SHA256SUMS.txt).
2. **Secrets استقرار Worker (یک‌بار):** در تنظیمات مخزن → Settings → Secrets and variables → Actions دو Secret بسازید: `CLOUDFLARE_API_TOKEN` (با مجوز Workers Deploy + D1 Edit) و `CLOUDFLARE_ACCOUNT_ID`. تا وقتی این دو ثبت نشده‌اند، workflow «Deploy Rahyab Afghanistan Worker» ناموفق می‌شود ولی بیلد APK جدا است و از کار نمی‌افتد. بدون استقرار Worker جدید هم برنامه کار می‌کند (Worker قدیمی فیلد client_uuid را نادیده می‌گیرد) — فقط تضمین ضدتکرار پس از استقرار فعال می‌شود.
3. **آزمون روی گوشی واقعی (بند ۱۰–۱۲ قانون):** چک‌لیست زیر.

## چک‌لیست آزمون عملی روی گوشی (کارفرما)

- [ ] نصب APK جدید روی نسخهٔ ۱٫۰٫۲ موجود — تأیید: تنظیمات و گزارش‌های قبلی پاک نشده‌اند
- [ ] ثبت گزارش «ترافیک متوسط» و «ریزش کوه و سنگ» (دو نوع جدید) → پیام ثبت موفق
- [ ] با اینترنت روشن: گزارش ثبت کنید → در تنظیمات پیشرفته POI شمارندهٔ «در انتظار ارسال» صفر شود
- [ ] با اینترنت خاموش: دو گزارش ثبت کنید → شمارنده ۲ بماند → اینترنت وصل شود → صف خودکار (یا با بستن و بازکردن برنامه) ارسال و شمارنده صفر شود
- [ ] دو بار همان گزارش را ثبت و در فاصلهٔ ارسال، اینترنت را در لحظهٔ ارسال قطع کنید → بعد از وصل شدن، در سرور فقط یک نسخه ثبت شده باشد (ضدتکرار)
- [ ] در سایت داشبورد (یا `GET /api/v1/reports`) گزارش‌های ارسالی از گوشی دیده شوند؛ روی گوشی دوم گزارش‌های دیگران روی نقشه ظاهر شود
- [ ] GPS را خاموش کنید → مسیریابی را شروع کنید → گفت‌وگوی «روشن‌کردن موقعیت‌یاب» باز شود → تنظیمات اندروید → روشن کنید → برگردید → مسیریابی خودکار شروع شود
- [ ] زبان انگلیسی → پنجرهٔ گزارش و برچسب رادیو انگلیسی باشند؛ زبان پشتو → همان با پشتو
- [ ] هشدار صوتی نوع‌های جدید: نزدیک یک گزارش «انسداد موقت» بروید → صدای انسداد پخش شود
