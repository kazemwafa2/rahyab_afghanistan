## ۳. یافته‌های حیاتی ممیزی

### ۳-۱. گزارش حوادث به سرور وصل نیست (مهم‌ترین شکاف)
- `ReportsModule.kt` گزارش‌ها را فقط در SQLite محلی (`reports.db`) ذخیره می‌کند و **هرگز** به `POST/GET /api/v1/reports` درخواست نمی‌زند.
- نتیجه: گزارش تصادف/ترافیک/خطر کاربران فقط روی گوشی خودشان دیده می‌شود؛ دیگران هرگز نمی‌بینند؛ جدول `live_reports` سرور همیشه خالی می‌ماند.
- برخلاف سیستم POI که کامل وصل است (`RoadPois.kt` همهٔ ۷ مسیر POI را صدا می‌زند + صف آفلاین `pending_ops` دارد).

### ۳-۲. آدرس API در اپ جای‌نگهدار است
- `Config.kt:54`: `POI_API_BASE = "https://rahyab-worker.YOUR-ACCOUNT.workers.dev"` — یعنی سیستم POI در APK منتشرشده فعلاً آفلاین می‌ماند.
- `RoadPois.kt:218`: `serverConfigured()` هر URL شروع‌شده با http را «تنظیم‌شده» می‌داند — جای‌نگهدار هم قبول می‌شود (باید رد شود).

### ۳-۳. بدهی بومی‌سازی (علت باگ «دو گزینه در انگلیسی فارسی می‌مانند»)
رشته‌های دری به‌صورت هاردکد در کد Kotlin (نه از strings.xml):
- `WeatherModule.kt:90-125` — تمام شرح وضعیت هوا و AQI
- `ReportsModule.kt:70-94` — برچسب انواع گزارش؛ `:150-152` پیام‌های خطا
- `MapPackagesActivity.kt:311,336,454,477` — متن‌های مدیریت پکیج‌ها
- `TrafficModule.kt:103-111` — رنگ‌ها و عنوان پیش‌فرض «ترافیک»
- `RadioModule.kt:23-31` — نام ایستگاه‌ها و دسته‌ها
- `MainActivity.kt:1063,1911,1927` — چند Toast
- `values-fa/` فایل `strings_pois.xml` ندارد؛ `values-en/` و `values-ps/` فایل `strings_dictionary.xml` ندارند.

### ۳-۴. جریان فعال‌سازی GPS ناقص است (بخش ۴ سند)
- `NavigationController.kt` وضعیت `isProviderEnabled` را چک می‌کند اما **هیچ‌جا** `ACTION_LOCATION_SOURCE_SETTINGS` باز نمی‌شود — یعنی صفحهٔ رسمی روشن‌کردن GPS در اولین اجرا وجود ندارد.
- `WelcomeActivity` فقط توضیح مجوز دارد.

### ۳-۵. دوربین ناوبری — نتیجهٔ بررسی مشکل گاه‌به‌گاه
منطق پیگیری دوربین بررسی شد (`MainActivity.onFixDuringNav` خط ۱۳۸۸-۱۴۳۶): دنبال‌کردن خودکار روی نقطهٔ Snap، زوم ۱۷.۵، تیلت ۴۵ درجه، توقف ۵ ثانیه‌ای پس از لمس کاربر — **باگ قطعی در این مسیر یافت نشد**.
طبق دستور کاربر («اگر مشکل را پیدا کردی حل کن، اگر نه دست نزن») کد دست‌نخورده ماند. علل محتمل (در انتظار شرح علائم از کاربر):
- انیمیشن دوربین هر ۱ ثانیه دوباره شروع می‌شود و با انیمیشن قبلی در حال اجرا می‌جنگد (در دستگاه‌های کند می‌تواند پرش تصویری بدهد)
- حین ناوبری فقط `navPanMs` کنترل می‌کند و تیک `followUser` نادیده گرفته می‌شود
- بازگشت از پس‌زمینه/تماس تلفنی ممکن است دوربین را ریست کند (نیازمند تأیید علائم)

### ۳-۶. traffic.geojson — پرونده بسته شد
- فایل واقعی در `traffic/traffic.geojson` در مخزن است (FeatureCollection خالی به‌صورت عمدی — سیاست پروژه: هیچ دادهٔ ترافیک جعلی منتشر نمی‌شود).
- اپ از `raw.githubusercontent.com/kazemwafa2/rahyab_afghanistan/main/traffic/traffic.geojson` استفاده می‌کند (`TrafficModule.kt:29`) و لینک قدیمی `releases/download/map-data/traffic.geojson` به‌صورت خودکار به همین URL مهاجرت می‌کند (`TrafficModule.kt:33,53,60`). پس ۴۰۴ قدیمی اثر باقی‌ماندهٔ لینک قدیمی بود و کد جدید آن را خودکار اصلاح می‌کند.

### ۳-۷. ناسازگاری‌های فرعی
- `worker/wrangler.toml`: نام ورکر `rahyab-worker` است ولی ورکر مستقر `rahyab-api` نام دارد؛ `database_id` هنوز `REPLACE_WITH_YOUR_D1_ID` است.
- `docs/PUBLISH.md:6` به مخزن `rahyab-afghanistan/rahyab-afghanistan` ارجاع می‌دهد (کهنه است).
- دو ورک‌فلو ساخت نقشه ابزار متفاوت دارند (planetiler 0.8.2/JDK21/Py3.12 در برابر 0.8.3/JDK17/Py3.11).
- `strings_dictionary.xml` با ۱۳۴ کلید هیچ‌جا استفاده نمی‌شود (منبع مرده).

## ۵. طرح اجرای مرحله‌ای (اصلاح‌شده بر اساس ممیزی)

- **مرحلهٔ ۱-۲ (انجام شد):** همین سند + آزمایش اتصال زنده.
- **بستهٔ اصلاح ۱ (مرحلهٔ ۳ سند):** وصل‌کردن `ReportsModule` به `POST/GET /api/v1/reports` با صف آفلاین به الگوی `pending_ops`؛ تنظیم `POI_API_BASE` روی آدرس واقعی + بستن حفرهٔ `serverConfigured()`؛ رفع کامل بدهی بومی‌سازی (همهٔ رشته‌های هاردکد → strings.xml با ترجمهٔ انگلیسی و پشتو)؛ افزودن جریان رسمی فعال‌سازی GPS در اولین اجرا؛ همگام‌سازی `wrangler.toml`.
- **مرحلهٔ ۴:** تکمیل GPS حین رانندگی/پس‌زمینه بر اساس الزامات بخش ۴ (فیلتر دقت، کاهش ارسال در توقف، رفتار پس از قطع GPS).
- **مرحلهٔ ۵:** موتور تشخیص خودکار ترافیک — جدول‌های `road_segments`، `traffic_segment_stats`، `traffic_observations`، `traffic_alerts`، `schema_migrations` با Migration مستند؛ ارسال تجمیعی سرعت از اپ؛ منطق آستانه‌های ۶۰/۳۵/۲۰٪ و حداقل رانندگان سمت سرور.
- **مرحلهٔ ۶:** هشدار مسیرمحور و جهت‌محور (اشتراک مسیر، فاصله‌بندی ۵۰۰م-۵کیلومتر، پیام صوتی دری سند).
- **مرحلهٔ ۷:** تقویت آفلاین/همگام‌سازی (فلاش خودکار صف‌ها پس از اتصال — بدون افزودن وابستگی جدید).
- **مرحلهٔ ۸:** به‌روزرسانی از GitHub — موجود است، فقط بازبینی.
- **مرحلهٔ ۹:** تست واحد برای هر موتور جدید + آزمایش‌های فهرست بخش ۱۷.
- **مرحلهٔ ۱۰:** Build از طریق GitHub Actions، تنظیم Secretهای امضا، انتشار Release، مستندسازی نهایی.

**نحوهٔ Build و تست پس از هر مرحله:** SDK اندروید در محیط توسعهٔ ما نیست؛ ساخت و تست واحد در GitHub Actions اجرا می‌شود (ورک‌فلوی Build APK). تغییرات هر مرحله به‌صورت بستهٔ فایل‌های تغییریافته + اسکریپت اعمال برای ترموکس تحویل می‌شود تا شما پوش کنید.
